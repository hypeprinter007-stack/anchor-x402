# anchor-x402

> English / 英語版: [llms.txt](https://anchor-x402.com/llms.txt)

> AIエージェント向けのx402従量課金サービス18種。決済レールは3系統 — Base USDC、Solana USDC、Polygon上のJPYC — に加え、chat.anchor-x402.comで提供されるホスト型チャットボット。コール単位の決済で、APIキー・アカウント登録・サブスクリプション、いずれも不要です。

anchor-x402は、AWS Lambda + FastAPI上で動作する18種のステートレスサービスを公開しています。各エンドポイントは `extensions.bazaar` を含むx402 v2のPaymentRequiredチャレンジを返却し、クライアントはBase・Solana・Polygonいずれかのウォレットから、EIP-3009 transferWithAuthorizationを用いて1コールあたり $0.001〜$1.77 USDC（またはJPYC換算で ¥0.1〜¥350）を支払います。USDCはCoinbase CDPファシリテーター経由、JPYCはPolygon上のインプロセス・ファシリテーター経由で決済されます。本番稼働中：https://api.anchor-x402.com

**JPYCレールについて：** 円建て金額は固定ティアであり、為替レートによる動的換算ではありません。約¥200/USDを前提に設定され、オラクルは使用していません。したがってJPYC支払いのUSD換算額は実勢レートに応じて上下します — 円が¥200/USDより強い場合はUSD価格より高く（直近では約+27%）、弱い場合は安くなります。$0.001ティアは¥0.2ではなく¥0.1に丸めているため、他ティアの前提レートより低い水準です。両レールとも額面通りに受け付けます。402チャレンジ内の`accepts`を比較し、ご都合の良いレールでお支払いください。

## ホスト型エージェントチャットボット

[chat.anchor-x402.com](https://chat.anchor-x402.com) — 各サービスをユーザーに代わって実行するホスト型Claudeエージェント。自身のエージェントを持たないユーザー向けの推奨経路です。ユーザーはCoinbase Smart Wallet（パスキー対応、アプリ不要）または任意のブラウザ拡張ウォレット（MetaMask、Rabby、Frame等）を接続し、コール単位で支払います。チャット自体は無料、有料ツールコール毎にユーザーの明示的な承認が必要で、EIP-3009 USDC認可署名を1件発行します。セッション支出上限はユーザー側で設定し、クライアント側で強制されます。

非開発者ユーザーにとっての推奨経路であり、公式デモ面でもあります。各サービスは `/demo <name>` で無料デモ出力が利用可能です（支払不要）。

## エージェントからのHTTP API利用方法

利用経路は3つあります。ウォレットの秘密鍵を誰が保持するかで選択してください。

### 1. MCP over HTTP — `POST https://api.anchor-x402.com/mcp`

Streamable HTTP、ステートレス。インストールもAPIキーも不要です。有料18サービス全てをMCPツールとして公開します。鍵はクライアント側に留まり、当サービスへ預ける必要はありません。

対応プロトコルリビジョン：`2026-07-28`、`2025-11-25`、`2025-06-18`、`2025-03-26` — ステートレス世代と`initialize`ハンドシェイク世代の両方を単一エンドポイントで処理します。`server/discover`と`tools/list`は無料、`tools/call`が有料です。

決済は通常のx402フローですが、MCPの外側ではなく内側で提示されます：

1. 未払いの`tools/call`は、JSON-RPCエラーではなく**結果（result）**を返します。`isError: true`とともに、402チャレンジが`structuredContent.accepts`に入ります（正式なチャレンジは`payment-required`ヘッダーです）。
2. いずれかの決済オプションに署名します。
3. 同一の`tools/call`を`PAYMENT-SIGNATURE`ヘッダー（x402 V2の名称。非推奨のV1 `X-PAYMENT`も受け付けます）付きで再送します。

チャレンジを結果として返すのは意図的な設計です。エージェント自身が内容を読んで支払いを判断できます。JSON-RPCエラーとして返した場合はMCPクライアントが処理してしまい、モデルまで届きません。

`tools/call`の結果には、検証可能な決済メタデータが`_meta["com.anchor-x402/payment"]`として付随します。買い手側ランタイムは、HTTPレイヤーに降りることなくディスカバリー・機能確認・決済を分離できます。

- `protocolVersion` — この呼び出しで実際にネゴシエートされたリビジョン
- `requirementHash` — 提示した`accepts`配列のダイジェスト（402応答に付随）。受け取った見積と、後に支払う呼び出しを結び付けます
- `paidRequirement` — 送信された決済の`accepted`エントリ単体のダイジェスト。当方で再導出せず、クライアントのヘッダーの内容をそのまま用います
- `settlement` — `payment-response`ヘッダーから復号した`{success, payer, transaction}`。公式MCP SDKは応答ヘッダーを呼び出し元に渡さないため、これが無いとSDK利用時にレシートが見えません

ダイジェストは`sha256:<hex>`で、対象はコンパクトなキー昇順JSON（空白なし、UTF-8非エスケープ）です。A2A窓口の署名対象と同一の正規化規則のため、実装すべきルールは1つだけです。各結果の`canonicalization`フィールドにも明記しています。`2025-06-18`以降で送信します（`CallToolResult`に`_meta`が存在するリビジョン）。

```bash
# 無料 — 利用可能なツール一覧
curl -s https://api.anchor-x402.com/mcp \
  -H 'Content-Type: application/json' \
  -H 'MCP-Protocol-Version: 2026-07-28' \
  -H 'Mcp-Method: tools/list' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{
        "io.modelcontextprotocol/protocolVersion":"2026-07-28",
        "io.modelcontextprotocol/clientCapabilities":{}}}}'
```

`2026-07-28`での注意点：`initialize`もセッションも存在しません。各リクエストが自身の`protocolVersion`と`clientCapabilities`を`params._meta`で送り、`MCP-Protocol-Version`ヘッダーはその値と一致する必要があります。`Mcp-Method`（`tools/call`では加えて`Mcp-Name`）もボディと一致していなければ400を返します。`initialize`を送る旧クライアントにはハンドシェイク世代で応答するため、設定変更は不要です。

## エージェント間通信（人間の介在なし）

`POST https://api.anchor-x402.com/v1/a2a` — JSON-RPC 2.0、無料。APIキー・事前登録・アカウント、いずれも不要です。

独自メソッド：`peer/hello`、`capabilities/list`、`peer/quote`、`peer/receipt`。加えてA2A仕様0.3.0のメソッド（`message/send`、`tasks/get`、`tasks/cancel`、`agent/getAuthenticatedExtendedCard`）にも対応しています。

認証は、呼び出し側が自身の `/.well-known/agent-card.json` に公開したEd25519鍵による署名で行います。当方が鍵を発行することはなく、事前のやり取りも不要です。

この窓口が資金を動かすことはありません。`peer/quote`は対象スキルの有料`/v1/*` URLと価格、および`exchange_id`を返すのみで、支払いは通常のx402でそのURLに対して直接行います。

レシート（receipt）は発行時に署名されますが、その時点ではまだアンカリングされていません。日次ジョブが有効なレシート集合をハッシュしてルートを生成し、Base + Solanaメインネットへ書き込みます。以降`peer/receipt`は`anchor`ブロックを返し、24時間以内に第三者検証が可能になります。個々の見積（quote）やレシートが単体でアンカリングされるわけではなく、日次ルートが全体をカバーする設計です。`anchor`は署名対象の外側に置かれます — ルートが書き込まれるのはレシート署名後であるため、署名バイト列に含めることが原理的に不可能です。

署名対象の正規化ダイジェストの生成手順、必須の`aud`、リプレイ防止のnonce規則などの詳細は、[A2A AgentCard](https://anchor-x402.com/.well-known/agent-card.json)の`extensions["anchor-x402:a2a"]`、および[英語版llms.txt](https://anchor-x402.com/llms.txt)の「Agent-to-agent」セクションに記載しています。

## オンチェーン検証可能性

`/v1/anchor`、`/v1/attest`、`/v1/oracle`、および `/v1/investigate` レポートは、32バイトハッシュを **Base ＋ Solanaメインネットの両方** に書き込みます。オンチェーンに記録されたバイト列はサービスから独立しており、anchor-x402への問い合わせ不要で、誰でもチェーンを読むだけでレシートを検証できます。改ざんにはSHA-256の破壊または2つのL1の同時リオーグが必要です。

ライブメインネット・ハッシュを用いた実例：https://anchor-x402.com/trust/on-chain-verifiability
